# Roblox Gameplay Portfolio

Gameplay systems in Luau by [totallean](https://totallean.github.io). Each place is built around one
mechanic that is hard to get right: server-authoritative where it matters, RU/EN localized, laid out for
[Rojo](https://rojo.space). The demo maps are deliberately minimal greybox layouts generated by code
(`build/BuildMap.luau`): the point is the systems, not the art.

Released game: [Spectrum Forge](https://www.roblox.com/games/90164767787037/Spectrum-Forge) on Roblox.

| Place | Mechanic | Highlights |
|---|---|---|
| [WebSwing](WebSwing) | Spider-Man style web swinging | custom pendulum physics, smart anchor selection, replicated webs, ring race with global leaderboard |
| [HorrorStalker](HorrorStalker) | Stealth horror NPC that sees, hears and hunts you | vision cone + light + line of sight, hearing from measured speed, 6-state AI with pathfinding, hiding lockers, jumpscare |
| [ButterSquishTycoon](ButterSquishTycoon) | Factory tycoon | config-driven production line, plots, achievements, monetization, session-locked saves, onboarding |

## WebSwing — web swinging

**Controls:** hold LMB / R2 to swing, Q / L2 web zip, hold Shift / L1 to reel in, Space to jump off the web.
Mobile buttons are created automatically.

Ready-to-open place file: [`WebSwing/WebSwing.rbxl`](WebSwing/WebSwing.rbxl).

- **Pendulum physics on top of Roblox physics.** The character is switched to `PlatformStand` and its
  velocity is corrected every `PreSimulation` step: the outward radial component is replaced by an
  inward one proportional to rope stretch, so the radius stays stable without teleporting. Input pumps the
  swing only along the arc tangent; gravity is scaled down while airborne for a floatier arc.
- **Anchor selection like the console games.** An ideal point ahead of and above the player is projected
  sideways onto the nearest facade, so the web lands on the side of the street and the arc runs along it.
  A fan-of-rays fallback covers plazas and rooftops. The physics pivot sits a few studs off the wall so the
  bottom of the arc doesn't scrape it.
- **Ground clearance:** the lowest point of the arc is kept above the street, so a low web lifts you
  instead of dragging you along the asphalt.
- **Game feel:** body aligned to the rope with `AlignOrientation`, right arm IK-aimed at the web
  (shoulder `Motor6D`), web shoot/retract animation, speed-based FOV, camera shake, wind streaks.
- **Multiplayer:** clients announce attach/release; the server validates type, range and rate (token
  bucket) and rebroadcasts, so everyone sees everyone's webs.
- **Ring race:** 8 rings around a greybox loop, timed on the server with a segment-vs-disc crossing test (works at 200+ studs/s),
  personal best in `leaderstats`, global top-10 on an `OrderedDataStore` board with an in-session fallback.

## HorrorStalker — the NPC that sees you and attacks

**Controls:** Shift run (loud), C crouch (quiet, harder to see), F flashlight, E hide / take keys,
**G shows the AI's vision** (debug overlay for demoing the AI).

Ready-to-open place file: [`HorrorStalker/TheStalker.rbxl`](HorrorStalker/TheStalker.rbxl).

- **Perception.** Vision = horizontal view cone + small "sixth sense" radius + raycast line of sight to head
  and torso. View distance scales with how lit you are (static lamp map), your flashlight and crouching.
  Awareness fills gradually (faster when close or lit) and decays when you break line of sight.
- **Hearing from measured speed**, not from what the client reports: the server reads the character's
  actual velocity, and "crouched" only counts while the body really moves at crouch speed.
- **State machine:** Patrol → Investigate → Search → Chase → Extract / Attack, with `PathfindingService`
  (async path requests with stale-result tokens, waypoint following, stuck detection) and direct pursuit
  when it has line of sight at short range. After losing sight it keeps tracking you for a few seconds,
  then searches around the last place it saw you.
- **Lockers:** hide to break line of sight. If it saw you get in, it walks over and pulls you out.
- **Light "director":** patrol drifts toward players now and then so careful play still feels hunted.
- **Safe room:** the start cell is never seen, heard or patrolled, which also prevents spawn kills.
- **Robust navigation:** unreachable goals are dropped and re-picked, repeated stuck detection gives up
  on a goal instead of walking into a wall.
- **Studio-only dev tools** (`ServerStorage.HorrorDevTools`, created only when `RunService:IsStudio()`):
  freeze the stalker, force-hide a player, read the AI state — used for automated QA and for filming.
- **Feedback:** awareness "eye" UI, red vignette and heartbeat scaled by danger, lamps flicker near the
  stalker, stingers on detection, first-person head bob, scripted jumpscare camera.
- **Main menu with a live 3D cover:** the camera dollies down a dark corridor toward a posed stalker under
  a flickering bulb with a red rim light; fog is thinned client-side for the shot, controls are locked and
  the HUD hidden while the menu is open.
- **Game-over screen** (time survived, keys found) with Restart / Main menu. Respawns are server-driven
  (`CharacterAutoLoads = false`): the client asks for a respawn, and a solo restart starts a fresh round.
- **Round loop:** 3 keys at random spots in a 6×5 maze, exit opens when all are found, co-op escape and round reset.

## ButterSquishTycoon — factory tycoon

Butter sticks leave the extruder, get stamped and coated in up to five layers of wax, then sell at the
collector. Source in `ButterSquishTycoon/src`: 13 server services, 4 shared modules, 2 client controllers.

- **Content-driven design.** `Shared/Config.lua` is the single source of content: stations, buttons, prices,
  palette and plot layout. Logic never names a specific station, so a new production step is one table entry.
- **Plots and purchases:** six plots with claim pads, purchase buttons that pop in with `TweenService`,
  belt boosts and rebirths.
- **Retention:** achievements with cash rewards and a collection bonus, and a first-time-user tutorial
  (`FTUEController`).
- **Monetization:** game passes (x2 value, auto-collect, VIP aura, starter pack) and developer products,
  handled in `MonetizationService`.
- **Network contract:** every remote is registered through `NetService` with an argument schema
  (`Shared/Schema.lua`) and a per-remote rate limit; invalid calls are rejected before any handler runs.
- **Social:** server-wide announcements for joins, rebirths and new stations, plus a leaderboard.
- **Saving:** `UpdateAsync` with session locking, autosave and a `BindToClose` that waits for pending writes.

The place file `ButterSquishTycoon.rbxl` opens directly in Studio; `default.project.json` maps `src/` for Rojo.

## Building a place from this repo

The quickest way is to open a ready place file (`WebSwing/WebSwing.rbxl`, `HorrorStalker/TheStalker.rbxl`,
`ButterSquishTycoon/ButterSquishTycoon.rbxl`). To rebuild **WebSwing** or **HorrorStalker** from source:

1. Open a new Baseplate in Studio.
2. Run `build/BuildMap.luau` in the command bar to generate the map.
3. Sync `src/` with Rojo (`rojo serve <Place>/default.project.json`), **or** without Rojo:
   `python3 tools/make_installer.py <Place>`, start `python3 -m http.server 8765 --bind 127.0.0.1` in this
   folder and paste `tools/StudioInstall.luau` (set `PLACE`) into the command bar.

Global leaderboards and saves need the place published with *Studio access to API services* enabled.
